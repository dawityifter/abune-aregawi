# Household Membership Report + Admin Member Reports — Design

Date: 2026-07-18
Status: Approved

## Goal

1. Move the **Member Information** report out of the treasurer Payment Reports and into
   the Admin Panel, restricted to the `admin` role only.
2. Add a new **Household Membership Directory** report: on-screen (paginated),
   printable, and savable as PDF via browser print-to-PDF, optimized for Letter and A4.

## Backend

New controller `backend/src/controllers/memberReportController.js`; routes added to
`backend/src/routes/memberRoutes.js`, both `firebaseAuthMiddleware` +
`roleMiddleware(['admin'])`.

### `GET /api/members/reports/member-information`

Same payload as the current `/api/payments/reports/member_information`:
`{ reportType, generatedAt, totalActiveMembers, members: [{ id, first_name, last_name,
phone_number, spouse_first_name, spouse_last_name, spouse_phone }] }`.
The logic moves out of `memberPaymentController.js`; the `member_information` branch in
`generatePaymentReport` is deleted.

### `GET /api/members/reports/household-directory`

Query params (all optional):
- `include_inactive` — default false (active members only)
- `last_name` — case-insensitive substring match on head's last name
- `city` — case-insensitive substring match
- `membership_status` — maps to `members.registration_status`

Response:

```json
{
  "success": true,
  "data": {
    "reportType": "household_directory",
    "generatedAt": "<ISO>",
    "generatedBy": "<authenticated member's full name>",
    "summary": {
      "totalHouseholds": 0,
      "totalParishMembers": 0,
      "totalHeads": 0,
      "totalSpouses": 0,
      "totalDependents": 0
    },
    "households": [
      {
        "headId": 1,
        "householdName": "Abraham & Hana Tesfaye Household",
        "head": { "name": "Abraham Tesfaye", "phone": "+19725551234" },
        "spouse": { "name": "Hana Tesfaye", "phone": null },
        "dependents": [
          { "name": "Samuel Tesfaye", "relationship": "Son", "phone": null }
        ],
        "otherFamilyMembers": [{ "name": "…", "phone": null }]
      }
    ]
  }
}
```

Assembly rules:
- **Heads** = members with `family_id` IS NULL or `family_id = id` (after filters).
- **Spouse** = `dependents` row with `relationship = 'Spouse'` for the head; fallback:
  parse `members.spouse_name` (first token = first name, rest = last name, no phone).
- **Dependents** = the head's remaining `dependents` rows, sorted by `dateOfBirth`
  ascending (oldest first); rows without DOB come after, sorted alphabetically by
  first name then last name. Relationship passed through (Son, Daughter, Parent,
  Sibling, Other; null → omitted label).
- **otherFamilyMembers** = member records with `family_id = head.id` and `id != head.id`
  (respecting the active filter), listed after dependents, counted in
  `totalParishMembers` but not in heads/spouses/dependents counts.
- **Household name**: `"<HeadFirst> <HeadLast> & <SpouseFirst> Household"` when a spouse
  exists (per the approved mock, e.g. "Abraham & Hana Tesfaye Household" style —
  implemented as `"<HeadFirst> & <SpouseFirst> <HeadLast> Household"` when spouse's last
  name equals head's, otherwise `"<HeadFirst> <HeadLast> & <SpouseFull> Household"`);
  without spouse: `"<HeadFirst> <HeadLast> Household"`.
- **Sorting**: households by head `last_name`, then `first_name` (case-insensitive).
- `totalParishMembers` = heads + spouses + dependents + otherFamilyMembers.
- Excluded everywhere: dates of birth, financial data, notes, emails, login info.

## Frontend

### Admin Panel

- New tab **Reports** in `AdminDashboard.tsx` (`#reports` hash), visible and reachable
  only when `userRoles` includes `admin`.
- New component `frontend/src/components/admin/MemberReports.tsx` with a report
  selector: `member_information` | `household_directory`.

### Member Information (moved)

Flat table render extracted from `PaymentReports.tsx` essentially unchanged, now
fetching `/api/members/reports/member-information`. `PaymentReports.tsx` drops the
`member_information` option, its interface fields, render function, and endpoint
special-case.

### Household Membership Directory (new)

- Filter panel: active-only toggle (default on), last name, city, membership status;
  Generate button refetches.
- Summary card (households, parish members, heads, spouses, dependents, generated
  date/time, generated by) shown at the top; repeated at the end of the report body.
- Household list paginated on screen (client-side, 20 households/page).
- Each household: header (household name + head's member id), then Head / Spouse /
  Dependents in order; phone lines rendered only when present — no placeholders or
  em-dashes for missing values; dependents show relationship in parentheses.
- **Print / Save as PDF** buttons both call `window.print()`.

### Print CSS (`@media print` via Tailwind `print:` utilities)

- Hide filters/pagination/nav; show full household list (all pages).
- Header: church logo + church name + "Household Membership Directory" + generation
  date. Page numbers and margins come from the browser (works for Letter and A4).
- Summary block printed at beginning and end.
- `break-inside: avoid` on each household block so households don't split across pages.

### i18n

New `en` + `ti` keys in `src/i18n/dictionaries.ts` for: tab label, report names,
filters, summary labels, section labels (Head of Household, Spouse, Dependents,
Household Members), relationship labels, buttons.

## Testing

- Backend Jest (sqlite in-memory): household grouping incl. family_id links,
  spouse-from-dependents vs `spouse_name` fallback, dependent DOB sorting, filters,
  summary counts, and 403 for non-admin roles.
- Frontend: light render test for `MemberReports` household view (summary + household
  sections, phone hidden when absent).

## Out of scope (future enhancements)

Excel export, Ministry/Group filter, DOB display.
